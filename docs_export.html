1. Executive Summary & Concept

Phantom Strike is a real-time multiplayer browser party game tailored for 2 to 8 players joining instantly via 4-letter room codes. Players take the role of rival clandestine operatives who make simultaneous, hidden strategic choices each round.

Core Mechanic: Players lock in secret actions within 20 seconds. Once all inputs are collected (or timer expires), cards flip simultaneously in a synchronized cinematic reveal. The server authoritatively resolves conflicts, rewards foresight, and penalizes predictable moves.
  • Zero friction: No authentication, no database, no installations required. Cross-platform support across desktop, tablet, and mobile devices.
  • Authoritative Architecture: Clients render state and handle micro-interactions; all game rules, action arbitration, and scores are managed exclusively on the server.

2. Game Rules & Mechanics

2.1 Operative Actions

Action Targeting Mechanic & Interaction
⚔️ STRIKE Mandatory Opponent Target • Hit unshielded target: Attacker gains +2 pts, target loses −2 pts.
• Hit shielded target: Blocked! Attacker penalized −1 pt, defender gains +1 pt.
• Mutual Strike (A hits B, B hits A): Both players clash and lose −1 pt.
• Target vanished (Phantom): Strike strikes thin air (0 pts).
🛡️ SHIELD Self (No Target) • Blocks all incoming strikes during the round.
• Attack blocked: Shielder gains +1 pt, attacker penalized −1 pt.
• Idle shield (no attacks received): Shielder gains safe-play bonus of +1 pt.
👻 PHANTOM Self (No Target) • Operative vanishes into stealth; completely untouchable.
• Vanishing Bonus: Operative earns +1 pt.
• Tactical Recon: Private intelligence edge that secretly reveals one random opponent's action to the operative.

2.2 Scoring & Win Conditions

  • Score Floor: Players cannot drop below 0 points. Minimum score is clamped at 0.
  • Point Threshold Victory: First operative to reach or exceed 15 points wins immediately.
  • Round Limit Victory: If no player reaches 15 points within 10 rounds, the operative with the highest score wins.
  • Sudden-Death Tiebreaker: If multiple players are tied for the highest score at threshold or round 10, a sudden-death round begins. Only tied operatives act while other players spectate. If tied after 3 sudden-death rounds, co-winners are declared.

4.1 State Synchronization Lifecycle

  1. Client Connection: Connects via WebSocket to Node.js backend. Client maintains persistent socket instance.
  2. Lobby Assembly: Host creates room; players join using 4-character room code and claim unique avatars.
  3. Action Submission: During action phase, clients submit submit_action. The server logs the action to private memory and broadcasts a sanitized state where only hasSubmitted: boolean is visible to other players.
  4. Simultaneous Resolution: Once all players lock in or timer reaches 0, the server executes resolveRound(), applies rules, broadcasts round_revealed, and transitions smoothly through reveal, results, and subsequent rounds.
